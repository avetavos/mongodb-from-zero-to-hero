`$group` is where aggregation earns its name. It collapses many documents into one document **per distinct value** of a key you choose, and for each group it computes summaries with **accumulators**. This is the stage that answers "how many per genre", "average price per quantity", "cheapest title per genre". If you have written `GROUP BY` in SQL the instinct is the same; the spelling is different.

The lesson seeds the module's `sales` collection (200 000 orders `{ title, genre, quantity, price, buyer }`) and the `aplan()` helper from the module intro. Output was captured on mongo 8.3.11, mongosh 2.11.1 and Node driver 7.7.0 on one Mac; Python, Go and Rust tabs were each run once in a scratch program.

```js
// mongosh/grp-seed.js
const genres = ["fiction", "science", "history", "poetry", "comics"];
globalThis.aplan = (pipeline) => {               // one line per aggregate explain: what the first stage read, then the stages left in the pipeline
  const e = db.sales.explain("executionStats").aggregate(pipeline);
  const cursor = e.stages ? e.stages[0].$cursor : e, rest = e.stages ? e.stages.slice(1).map((s) => Object.keys(s)[0]) : [];
  const chain = (p) => { const out = []; for (p = p.queryPlan ?? p; p; p = p.inputStage) out.push(p.stage + (p.indexName ? "(" + p.indexName + ")" : "")); return out.join(" > "); };
  const s = cursor.executionStats;
  return chain(cursor.queryPlanner.winningPlan) + "  keys=" + s.totalKeysExamined + " docs=" + s.totalDocsExamined + (rest.length ? "  | left in pipeline: " + rest.join(" > ") : "");
};
for (let s = 0; s < 200000; s += 50000) {
  db.sales.insertMany(Array.from({ length: 50000 }, (_, k) => {
    const i = s + k;                                          // 500 titles, 5 genres, quantity 1..5, price 5..25, 1000 buyers (pseudo-random but repeatable)
    return { title: "T" + (i % 500), genre: genres[(i % 500) % 5], quantity: 1 + ((Math.imul(i, 2654435761) >>> 0) % 5), price: 5 + ((Math.imul(i, 40503) >>> 0) % 21), buyer: "b" + (i % 1000) };
  }), { ordered: false });
}
db.sales.createIndex({ price: 1 });
console.log("sales:", db.sales.countDocuments(), "orders");
```

## Grouping by a key

The `_id` of a `$group` stage is the grouping key - the field or computed value documents are bucketed by. Every other field is an **accumulator**: an expression that folds all documents of a group into one value. Here we total the copies per genre and count the orders (the trailing `$sort` is only there to make the printed order stable - more on that below). The Node.js tab runs on a three-order collection:

## The common accumulators

- `$sum` - adds a numeric expression, or counts with `$sum: 1`.
- `$avg` - the mean.
- `$min` / `$max` - smallest and largest value.
- `$push` - every value into an array, duplicates included.
- `$addToSet` - **distinct** values into an array.
- `$first` / `$last` - value from the first/last document **in the current order**.
- `$top` / `$bottom` (5.2+) - value from the top/bottom document of an explicit `sortBy`.

Grouping by `quantity` (1-5) and profiling each group. `$push` and `$addToSet` are turned into sizes so the output fits: 1 000 distinct buyers, but about 40 000 pushed (duplicates kept):

```js
// mongosh/grp-accumulators.js
const rows = db.sales.aggregate([
  { $group: { _id: "$quantity", avgPrice: { $avg: "$price" }, cheapest: { $min: "$price" }, priciest: { $max: "$price" },
              buyers: { $addToSet: "$buyer" }, allBuyers: { $push: "$buyer" } } },
  { $project: { avgPrice: { $round: ["$avgPrice", 2] }, cheapest: 1, priciest: 1, distinctBuyers: { $size: "$buyers" }, pushedBuyers: { $size: "$allBuyers" } } },
  { $sort: { _id: 1 } },
]).toArray();
console.log(rows.map((r) => JSON.stringify(r)).join("\n"));
assert.strictEqual(rows.length, 5);
assert.ok(rows.every((r) => r.distinctBuyers <= 1000 && r.pushedBuyers > r.distinctBuyers));       // $push keeps duplicates, $addToSet does not
```

## Group output is not sorted

```js
// mongosh/grp-unordered.js
const ids = db.sales.aggregate([{ $group: { _id: "$title", n: { $sum: 1 } } }]).toArray().map((r) => r._id);
console.log("first ten groups, exactly as returned:", ids.slice(0, 10).join(" "));
const sorted = [...ids].sort();
console.log("returned in sorted order?", ids.every((v, i) => v === sorted[i]));
```

```text
first ten groups, exactly as returned: T455 T50 T153 T381 T35 T164 T335 T372 T416 T129
returned in sorted order? false
```

The groups come back in an order the server chose (here a hash-table walk), and a later run or version may differ. If you need an order, add `$sort` after `$group`.

## $first needs a $sort

`$first` returns the value from whichever document reaches the group first. The manual says it is "only meaningful when documents are in a defined order" and to "add a preceding `$sort` stage" ([$first](https://www.mongodb.com/docs/manual/reference/operator/aggregation/first/), consulted 2026-09-30). Cheapest title per genre three ways:

```js
// mongosh/grp-first.js
const cheapestFirst = db.sales.aggregate([
  { $sort: { price: 1, _id: 1 } },
  { $group: { _id: "$genre", cheapestTitle: { $first: "$title" }, price: { $first: "$price" } } },
  { $sort: { _id: 1 } },
]).toArray();
const noSort = db.sales.aggregate([
  { $group: { _id: "$genre", firstTitleSeen: { $first: "$title" }, price: { $first: "$price" } } },
  { $sort: { _id: 1 } },
]).toArray();
const top = db.sales.aggregate([
  { $group: { _id: "$genre", cheapest: { $bottom: { sortBy: { price: -1, _id: 1 }, output: ["$title", "$price"] } } } },   // $bottom of a descending sort = smallest price
  { $sort: { _id: 1 } },
]).toArray();
console.log("$sort then $first :", cheapestFirst.map((r) => r._id + " " + r.cheapestTitle + " $" + r.price).join(" | "));
console.log("$first, no sort   :", noSort.map((r) => r._id + " " + r.firstTitleSeen + " $" + r.price).join(" | "));
console.log("$bottom (5.2+)    :", top.map((r) => r._id + " " + r.cheapest[0] + " $" + r.cheapest[1]).join(" | "));
assert.ok(cheapestFirst.every((r) => r.price === 5));
```

```text
$sort then $first : comics T14 $5 | fiction T0 $5 | history T7 $5 | poetry T28 $5 | science T21 $5
$first, no sort   : comics T4 $23 | fiction T0 $5 | history T2 $14 | poetry T3 $8 | science T1 $20
$bottom (5.2+)    : comics T29 $5 | fiction T15 $5 | history T22 $5 | poetry T8 $5 | science T36 $5
```

## Counting and grand totals

Set `_id` to `null` and every document falls into one group. `$count` and `$sortByCount` are shorthands for the two commonest groups:

```js
// mongosh/grp-count.js
console.log("grand total   :", db.sales.aggregate([{ $group: { _id: null, revenue: { $sum: { $multiply: ["$price", "$quantity"] } }, orders: { $sum: 1 } } }]).toArray());
console.log("$count stage  :", db.sales.aggregate([{ $match: { genre: "poetry" } }, { $count: "poetryOrders" }]).toArray());
console.log("$sortByCount  :", db.sales.aggregate([{ $sortByCount: "$genre" }]).toArray().slice(0, 2), "...");
console.log("empty input   :", db.sales.aggregate([{ $match: { genre: "none" } }, { $group: { _id: null, n: { $sum: 1 } } }]).toArray(), "<- no group at all, not n: 0");
```

```text
grand total   : [ { _id: null, revenue: 8963632, orders: 200000 } ]
$count stage  : [ { poetryOrders: 40000 } ]
$sortByCount  : [ { _id: 'poetry', count: 40000 }, { _id: 'history', count: 40000 } ] ...
empty input   : [] <- no group at all, not n: 0
```

## Memory: when a group does not fit

`$group` keeps its groups in memory (100 MB by default, `internalDocumentSourceGroupMaxMemoryBytes`). This run pushes every 1 KB pad of a 130 MB collection into 1 000 groups, so the working set exceeds the limit:

```js
// mongosh/grp-spill.js
for (let s = 0; s < 130000; s += 10000) db.big.insertMany(Array.from({ length: 10000 }, (_, k) => ({ n: s + k, pad: "x".repeat(1000) })), { ordered: false });
const p = [{ $group: { _id: { $mod: ["$n", 1000] }, pads: { $push: "$pad" }, docs: { $sum: 1 } } }, { $count: "groups" }];
console.log("collection MB:", +(db.big.stats().size / 1048576).toFixed(0), "| $group holds every pad in memory (~130 MB > 100 MB limit)");
let t = Date.now();
console.log("default            ->", db.big.aggregate(p).toArray(), Date.now() - t, "ms");
try { db.big.aggregate(p, { allowDiskUse: false }).toArray(); }
catch (e) { console.log("allowDiskUse:false ->", e.codeName + ":", e.message.slice(e.message.indexOf("Exceeded"), e.message.indexOf("Exceeded") + 100)); }
const e = db.big.explain("executionStats").aggregate(p.slice(0, 1));
const find = (s) => (s.stage === "group" ? s : s.inputStage ? find(s.inputStage) : null);
const g = find((e.stages ? e.stages[0].$cursor : e).executionStats.executionStages);
console.log("explain, group stage:", { usedDisk: g.usedDisk, spills: g.spills, spilledBytesMB: Math.round(g.spilledBytes / 1048576), peakMB: +(g.peakTrackedMemBytes / 1048576).toFixed(0) });
```

```text
collection MB: 129 | $group holds every pad in memory (~130 MB > 100 MB limit)
default            -> [ { groups: 1000 } ] 192 ms
allowDiskUse:false -> QueryExceededMemoryLimitNoDiskUseAllowed: Exceeded memory limit for $group, but didn't allow external spilling; pass allowDiskUse:true to opt 
explain, group stage: { usedDisk: true, spills: 2, spilledBytesMB: 125, peakMB: 101 }
```

## Tips and gotchas

- After `$group` only `_id` and the accumulators exist; carry other fields forward with `$first`, `$last`, `$push` or `$top`.
- `$sum: 1` counts rows; `$sum: "$quantity"` adds values. An empty input produces no group at all.
- `$push` keeps duplicates and order, `$addToSet` removes duplicates and promises no order.
- Grouping does not sort; add `$sort` (with a unique tie-breaker) when order matters.
- A group that outgrows 100 MB spills to disk by default; do not rely on that for hot paths - `$match` first and keep accumulators small.

<Callout title="Group collapses, accumulators summarise">
Picture `$group` as folding the stream by a key: one output document per distinct key. The accumulators decide what each fold remembers - a sum, an average, a set of values. Set `_id` to `null` to fold everything into one grand total.
</Callout>

## Reading AI-generated code

Asked for "the cheapest title in each genre", an assistant writes:

<SpotTheBug lang="js" code={`// AI comment: "$first takes the cheapest title per genre"
db.sales.aggregate([
  { $group: { _id: "$genre", cheapestTitle: { $first: "$title" }, price: { $first: "$price" } } },
]);`}>

There is no `$sort`, so `$first` is just "the first order the server happened to read". In the run above the unsorted version reported comics at **$23**, history at **$14** and science at **$20**, while every genre actually has $5 orders. Sorting before the group fixes it, and `$bottom` (or `$top`) says what you mean inside the accumulator; both returned $5 for all five genres, as the `first` block above shows. Note that the two correct answers can name different titles because many titles tie at $5 - add a tie-breaker (`_id`) to make the result repeatable.

</SpotTheBug>

## Mental Model

`$group` is a hash map from key to accumulator state, fed by the stream. Two consequences: the map has no order (so no sorted output), and the state lives in memory (so its size, not the input size, decides whether it spills). Accumulators that depend on arrival order (`$first`, `$last`, `$push`) are only as deterministic as the order you gave them.

## Trade-offs

| Choice | Benefit | Cost |
|---------|---------|------|
| `$group` in the pipeline | Returns only the collapsed result: 5 rows instead of 200 000 | Limited to MongoDB expressions; state must fit 100 MB or spill |
| Grouping in application code | Any logic | Moves every raw document first |
| `$sort` + `$first` | Deterministic pick | Sorts the whole stream first |
| `$top` / `$bottom` | Sort and pick in one accumulator | MongoDB 5.2+ only |
| `$push` of large values | Keeps everything | 130 MB working set spilled twice |

## Common Misconceptions

- **"Original fields survive `$group`."** - only `_id` and your accumulators do.
- **"`$group` returns groups sorted by key."** - the ten first titles came back as T455 T50 T153 ... and were not in sorted order.
- **"`$first` is the smallest value."** - it is the first document's value; unsorted it gave $23 where $5 existed.
- **"A `$group` over the memory limit errors."** - it spilled to disk (2 spills) unless `allowDiskUse: false`.
- **"An empty match gives `n: 0`."** - `$group` with `_id: null` over no documents returns `[]`.
